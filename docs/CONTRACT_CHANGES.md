# Contract changes

Agents propose changes to section 6 contracts here during a workflow round (BUILD_PLAN 0.3, 8.3).
The integrator decides between rounds, bumps `PROTOCOL_VERSION` in `types.py` for event changes,
and records the decision in CHANGELOG.md.

| # | Round | Agent | Proposal | Why | Decision |
|---|---|---|---|---|---|
| D1 | 0b-1 | D | **CLI wiring for `display` and `replay`** (cli.py, L): in `cli.main`, before argparse, `if argv and argv[0] == "display": return epitaph.display.remote.main(argv[1:])` and the same for `replay` → `epitaph.display.replay.main(argv[1:])`. Both parse their own flags (`display`: `--connect HOST --driver terminal\|screen --port --local-port --layout --theme --size WxH --fullscreen --fps --hardware --screen-present`; `replay`: `LIFE --speed --from mm:ss --driver terminal\|screen\|none --port --state-dir --max-gap --size --fullscreen --hardware`). | The stub parser (`_common` + REMAINDER) would swallow `--profile/--hardware` and does not know the display flags; delegating keeps one parser per command. | |
| D2 | 0b-1 | D | **`t` (life clock seconds) on every event**, not only `vitals`. The simulator already does it. | Replay needs the life clock for the original cadence and `--from mm:ss`; the status strip shows the life time. `ts` is wall time and is flat in the simulator. Replay falls back to `ts` when `t` is missing. | |
| D3 | 0b-1 | D | **Snapshot shape** (6.3 lists it loosely): `{v, ts, life, type:"snapshot", t, model, phase, mode, words:[{turn,i,text,state}], vitals:{…last vitals fields}, memory:{recall, recall_used}, open_turn?}`; `mode` ∈ `empty loading living reloading dying dead silence`; `open_turn` = the thought still being written. **Offer:** the controller can build it with `epitaph.display.layout.LifeView` fed through `bus.add_local(lambda e: view.handle(e, clock()))` and `snapshot=lambda: view.snapshot(clock())`, so the snapshot and the screen can never disagree. | Displays must redraw exactly after reconnect/overflow (fault matrix row "redraw within 5 s"). | |
| D4 | 0b-1 | D | **`word` event: add optional `hesitate_before_ms`** (it exists in `TimedWord`, not in 6.3's `word` fields) and optional `state:"inherited"` (V1.5). | Hesitations "sometimes inside a word" can go in `char_ms`; a hesitation before a word needs its own field so the cursor blinks through it. The display already honours both. | |
| D5 | 0b-1 | D | **Every memory cut emits `forget`, including the cut at a reload.** `sim.py` pops memory at a reload without a `forget` event. | Without it the display cannot fade what was lost at the life's biggest loss, and verify-life's "bright words in the last 2 minutes ≤ 40" cannot pass: in a simulated pi4/default life 285 words are still live at death. | |
| D6 | 0b-1 | D | **`sim.py` `birth_loading.t`** is the time since the previous life's clock start (the clock is started after the load). Suggest `t: 0` (or omit `t`) on `birth_loading`. | Harmless for the display (replay ignores a clock that goes backwards), but misleading in logs and verify. | |
| D7 | 0b-1 | D | **`[display]` additions** (config schema): `birth_card_seconds = 4`, `death_card_seconds = 8` (defaults in `ViewSettings` today). | Card timing is art, so it belongs in config (principle 4). | |
